# 报告质量合同：先判断用户价值，再验收执行

版本：`report-quality-v0.1`，2026-09-13。
状态：**本轮新制订的设计与验收标准；未接入生产、未完成样稿或效果验收。**
范围：AI热点报告与身体快报。不是生产日程指令，不会被当前模型自动加载。

## 1. 用户要买到的结果

- **热点报告**：以 Agent 为重点理解 AI 的重要变化，不是包含 Agent 关键词的 X 帖子摘要。看完知道最值得关注什么、为什么、要不要继续读或尝试。
- **身体快报**：在有限证据下得到有理由、可修正的身体状态判断，以及今天最值得做的一件事。不是仪表盘复读，也不是医疗诊断或未经校准的总分。
- 我们先承担这些产品假设并制作样稿，不要求用户先填写完整需求表；若用户认为范围或密度不对，修改并版本化假设。

### 本轮反馈的证据等级

用户报告已看到晨报，并指出重要倡议文章漏报、新闻偏少、健康内容缺乏判断。本轮未读取当日生产报告／调用记录，也未核实该文章原文与时间。因此这是明确的用户质量反馈，不是已完成的逐层漏报根因调查或准时性验收。

代码检查确认健康输出有结构性限制：
- `health-lab/src/garmin_readiness/brief.py` 预先生成观察／建议选项并固定渲染。
- `chat-lab/src/nimbus_chat_lab/garmin_client.py` 的 HEALTH_SYSTEM 要求模型只返回两个选项 ID；render 不采用自由分析。
- 趋势投影提供有限聚合，不等于把所有历史模式交给了主控。

所以不能把低价值全部归因于模型保守，也不能靠只改日程提示解决。该发现不意味着应该取消数字、隐私和安全校验。

## 2. 两份报告共同的判断合同

每份报告必须回答：
1. **我判断什么**：给出优先级或行动倾向，而不是罗列数据。
2. **为什么**：绑定决定判断的来源／事实；指出最有分量的反证或限制。
3. **对用户有什么用**：说明值得阅读、尝试、调整或保持什么。不为了显得有用而强迫行动。
4. **什么会改变判断**：给出可观察的新证据、条件或复核时间，而不是泛泛“持续关注”。

不确定性应限制具体断言，不能淹没整份报告。允许“暂时倾向于”“如果……则……”；不允许伪造精确概率、拟合结果或事实。

## 3. 三个独立验收轴

| 轴 | 判定 | 不可替代的边界 |
|---|---|---|
| 事实／安全 | pass / fail / unassessed | 数字、时间、来源、隐私、健康安全。任何硬失败不能靠文笔补偿 |
| 判断／价值 | pass / fail / limited / unassessed | 按两份专用标准审阅；传输和工具测试不能代替 |
| 执行／送达 | 实际完成状态、耗时、发送时间、阅读证据 | HTTP200、outbox sent、用户已读、准时分别记录 |

禁止把三个轴平均成一个总分。可以“安全但无用”，也可以“写得好但没按时到”。

质量状态语义：
- `pass`：该样本适用的硬门槛与价值门槛均已审阅通过，不代表稳定多日效果。
- `fail`：已观察到违约，例如重大事件遗漏、把旧数据当今天、只有数值复述。
- `limited`：材料／执行不足，只能提供有限报告；诚实降级不算完整质量通过。
- `unassessed`：没做评审，不能用“看起来不错”补填 pass。

拟议发布行为：事实或安全失败不发布受影响断言；仍可给有依据的其余内容。材料不足按既有单次日程给有限说明，不自动追加搜索、补发或无限等候。安全的事实降级稿可以送达，但必须记为“解读未完成”，不能算健康价值验收通过。此发布门禁尚未实现。

## 4. 评审方法：避免模型自评自证

- 模型可自查遗漏、矛盾、证据；自查不是最终验收。
- 审阅者先看输入证据和窗口，建立期望判断／允许的合理分歧，再看匿名候选稿；不能看哪版赢再调标准。
- 对重要性或行动建议存在分歧时记录理由和 adjudication（复核结论）；没有结论的项目保持未判，不偷偷删去失败样本。
- 用户只需对少量代表样稿评价“值得读／没用／建议不合适”并指出原因，不承担每日标注工作。
- 用户认可用于检验价值，不能豁免事实和健康安全；模型与模型互评不能冒充用户认可或医疗有效性。
- 所有下文样本量／阈值都是本版**初始产品门槛**，不是统计显著性、临床标准或已实测成绩。运行前冻结，修改则另记版本并重新评估。

## 5. 先样稿，后实现，再观察

1. **标准**（本轮）：冻结目标、失败例、审阅表。现有系统按新标准的完整基线仍待测。
2. **完整样稿**：每种报告至少三个有代表性的证据包；同证据生成旧／新稿，匿名并排审阅。新闻含重大跨主题事件／普通日／安静日；健康含一致信号／矛盾或换设备／数据缺失。
3. **冻结证据回放**：跑专用案例；新闻检索召回与编辑保留分别评估，健康解释质量与拟合预测分别评估。
4. **最小实现**：只改暴露出的信息或判断瓶颈。不先建第二 Agent 循环、全量新闻库或更复杂模型。
5. **有界真实验收**：按专用标准做未见样本与前瞻观察；失败保留，不重跑到成功。真实模型／搜索需要记录预算和数据范围；不默认发 Telegram。
6. **生产切换**：另行授权与维护，保留 scope 与回滚边界。更改准备 lead／成本也另行决策。

当前阶段不改 08:00／09:00、准备 lead、generation、工具、模型配置、健康数据或 Pi 插件；不执行拟合、生产重跑、发送、commit/push 或 memex 写入。

## 6. 通用验收记录模板

每次评审保存以下字段；含真实健康材料的整张表只存本机私有健康区域，不进 Git 或公共研究上下文。

```text
contract_version / evaluator / evaluated_at
sample_id / development_or_holdout / synthetic_or_real
input_snapshot_hash / available_at_cutoff / cutoff / timezone
baseline_output_hash / candidate_output_hash / model_and_policy_versions
expected_decisions / acceptable_alternatives / unresolved_labels
hard_gates: [{id, pass|fail|unassessed, evidence}]
value_dimensions: [{id, 0|1|2|unassessed, reason}]
missing_items / unsupported_claims / changed_decisions
verdict: pass|fail|limited|unassessed
execution: model_called, search_calls, latency, sent_at, read_evidence
review_disagreement / user_feedback / followup
```

没有来源快照不做“历史当时可知”承诺；没有真实调用不做“模型已通过”承诺。
