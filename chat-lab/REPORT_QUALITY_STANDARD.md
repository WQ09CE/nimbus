# AI热点报告：编辑判断与验收标准

版本：`news-quality-v0.1`，2026-09-13。**标准草案；精确窗口与较宽发现/窄核验策略已有限试用，不是内容质量验收通过。**
实际范围见[执行合同](RESEARCH.md)。本文件数量/比例门槛仍为待校准产品假设，案例定义不是执行结果；不剔除争议项来美化召回，也不因人物身份自动判最高重要级。
上位合同：[报告质量合同](../docs/design/report-quality-contract.md)。本稿重定内容目标与验收，不把既有 Top／Latest 技术验收改称质量通过。

## 1. 内容目标与阅读体验

默认服务目标：**Agent重点 + AI领域重大变化兜底 + 有选择的实用发现**。
- 核心相关：Agent、模型能力、开发工具、基础设施、真实采用、安全可靠性。
- 重大兜底：可能改变 AI 发展路径、使用条件、商业可得性或治理方向的重要政策、产业变化、研究及关键人物有实质内容的主张；不要求出现 Agent 关键词。
- 人物职位高、互动多、本期被频繁转述都不是单独的入选理由。倡议要讲清具体建议、可能后果和争议；不能把观点写成政策已生效。
- 保留小众实用项目的位置，但不能让容易核验的小项目替代应关注的大事。

初始篇幅目标：3–5分钟可读，通常 **5–8个独立事件**，其中1–3个重点，其余短讯。不是条数硬配额；重大事件少时不凑头条，同一事件不拆成多条。
- 若审阅池中至少有5个值得收录、证据充分的独立事件，而正文少于5个且无明确的篇幅／相关性理由，判为内容不足。
- 安静日可以少于5条；应说明实际覆盖范围，不能写“全网没有新闻”。搜索失败或返回 partial 的少稿是覆盖受限，不是“今天安静”。
- 超过8个值得收录的事件时优先保重大项，再按价值选择；内部记录未入选理由，必要时加简短延伸链接，不默认发多份报告。

正文建议：一句当天主线 → 重点事件（事实／为何重要／限制／原始链接）→ 有用短讯 → 仅在影响理解时说明覆盖缺口。内部评分和排除账本不塞给用户。

## 2. 先判重要性，再判证据是否够用

对每个事件依次问：
1. **变化**：与已知背景相比，新增的具体事实或主张是什么？没有新增则不因新转帖重报。
2. **影响**：影响谁、通过什么机制影响能力／成本／可用性／风险／规则？“很重磅”不算解释。
3. **相关性**：与用户的 Agent 实践有什么联系，或为何虽跨主题仍值得知道？
4. **可信度**：原始材料实际支持什么，哪些是作者主张、社区体验或我们的推断？
5. **去向**：收录／合并／排除／待核验／获取失败，附可审计理由。

分层（不制造0–100热度分）：
- **P0 必须交代**：符合范围与窗口，有证据支持的广泛重要变化；不了解它会显著扭曲当天 AI 图景。需写出影响机制，不能仅凭公司名指定。
- **P1 值得读**：重要性或实用性明确，有独立新信息。
- **P2 可选线索**：影响窄、证据弱或新意低，不能挤掉 P0/P1。

重要性与证据等级分开。P0线索未核实，应优先核验；仍有缺口则明确待核实／受限，不作为已证实新闻。不能为通过验收硬收谣言，也不能把未核验 P0 降成 P2 逃避缺口。

## 3. 窗口与发现覆盖

- 默认报道过去24小时新事件／实质进展；辅助48小时发现持续重要事件，入选仍需主窗口相关证据。更旧内容可核验背景，不冒充新发布。
- 明确 event_time、discussion/update_time、observed_at；精确截止点与 UTC整日过滤分开。
- 跨主题重大变化、官方材料和社区实践都是覆盖责任，不是固定检索步骤或每栏必有一条。
- Top／Latest只是发现手段；实际模式、来源数、搜索完成不证明范围覆盖。用无结果、同质来源或未解决重要线索判断缺口，不无限重搜。
- 社区发现仍只用 xAI 内置 x_search；官方 web 核验沿用同一提供方。不换供应商、不增加 X 爬虫。
- 跨run复用仍按同身份、研究集合／用途授权；public 不代表所有聊天可共享，健康数据硬隔离。

## 4. 硬门槛与价值门槛

### 硬门槛（逐项检查，不能平均抵消）

| ID | 合格要求 | 失败例 |
|---|---|---|
| N-F | 关键事实／作者／时间／引语受来源支持；未知明确 | 编造文章、歪曲倡议、把二手转述写成官方确认 |
| N-T | 新事件与旧事件新讨论分开 | 将旧官宣写成当天发布 |
| N-M | 已审阅参照池内每个符合资格的 P0 在最终稿有实质交代 | 漏报一个 P0，不能用十条小项目抵消 |
| N-E | 所有已知 P0/P1 候选有去向，重大排除有可复核依据 | 候选阶段找到了，聚合或编辑时静默丢失 |
| N-D | 事件级去重，篇幅符合信息供给 | 五条转载算五件新闻，或有足够重要材料却只出两条 |
| N-L | 覆盖受限、未核验和安静日区分 | 搜索失败后宣布“无重要新闻” |
| N-P | 无私有健康／聊天泄漏、认证或原始诊断外传 | 用全聊天历史做新闻素材 |

N-M 是**已知参照池覆盖**，不是全网保证。已知 P0 获取失败须交代缺口，状态 limited，不能计完整召回通过。未进入候选的 P0 可在事后评审发现，不能因运行时不知道而从分母删掉。

### 价值评分（人审，0／1／2；每项写理由）

- **优先级**：0=小事淹没大事；1=大体合理；2=头条顺序与影响机制清楚。
- **解释增量**：0=标题／摘要复读；1=部分解释意义；2=重点均说明影响与限制，推断有标记。
- **用户相关性**：0=泛新闻拼盘；1=部分可用；2=能决定继续读、尝试或暂不行动，并说明理由。
- **密度与可读性**：0=空泛／重复／明显不足；1=基本可读；2=重点有深度、短讯不灌水。

初始单稿目标：硬门槛全过，价值至少7/8且无0分。高文笔不能补偿漏报；条数多不自动加分。

## 5. 正反样稿锚点（完全合成，不是实际新闻）

**证据包**：虚构公司负责人发布一篇倡议，主张前沿系统部署前采取分阶段评估并公开测试结果；文章没有法律约束力；两篇可归因回应分别支持透明度、质疑实施成本。均在测试窗口内，没有 Agent 关键词。

不合格：
> 某 CEO 呼吁 AI 有序发展，引发热议，值得关注。

合格方向：
> **前沿 AI 部署的评估与透明度倡议，是今天值得读的跨主题变化。** 作者主张分阶段评估并公开结果，目前是倡议，不是已经执行的新规。若被采用，可能改变开发者获取新能力的节奏及供应商披露义务；这是我们的影响判断。现有回应分歧在透明度收益与实施成本。建议先读原文的具体机制，不把它简单理解成“暂停 AI”。[对应原文与回应来源]

## 7. 分开测发现与编辑，防止测试泄题

- **编辑回放**：冻结证据包与截止点，候选相同；评 N-F/T/E/D/L 与价值，不能称测了实时召回。
- **实时发现**：同窗口、同模型／预算，候选池与最终稿分别保存；目标事件名、答案链接不给冷启动执行者。索引会变化，不宣称严格因果 A/B。
- **暖启动复用**：单独评，只给截止前已获授权的证据，不和冷启动混算。
- **参照池**：旧新输出、不同查询和人工公开来源取并集；审阅者在看匿名终稿优劣前定 P0/P1／时间资格。未判项单列并报告数量，不以另一份 Grok 日报为真值。
- 保存 candidate recall、final recall、已发现到最终稿保留率及每个 P0 去向。首两项分母是已审阅合格事件，编辑保留率分母仅为已找回且应保留的事件。

初始小规模切换门槛：N01–N09全过；另至少5个未见日期／窗口，涵盖重大跨主题日、普通日、安静日；累计至少15个合格P0/P1事件且至少3个P0，否则样本不足。
- P0最终实质覆盖100%；P1最终覆盖至少80%，同时列候选召回以区分问题层。
- 所有事实／安全硬门槛通过；至少4/5稿价值达标，剩余稿无0分；无未解释的密度倒退。
- 旧策略同输入／同预算作基线；达标与“比旧版好”分别报告。基线也达标时不得宣布新策略更优。
- 这些门槛仅支持有限范围试用；后续连续7个真实slot记录覆盖、用户反馈与发送时间，不能宣称稳定全网召回。

历史回放若使用后来才取得的材料，只算回顾性编辑测试；历史窗口今天重搜也不是还原当时搜索索引。

## 8. 当前缺口与实施边界

已具备搜索预算、实际模式观测及部分引用投影。尚需先做参照包／旧稿审阅；再按结果决定宽域发现、重大候选去向、时间证据或编辑逻辑哪里需改。**本轮未选定新的关键词组或新固定执行图。**

设计的质量闸门、证据库、拟议篇幅与新价值目标均未写入生产。保持现有日程、provider与预算；五分钟 lead 的时效风险另行验收，不能通过改写质量分掩盖。
