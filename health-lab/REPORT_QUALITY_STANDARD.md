# 身体快报：判断、行动与探索性拟合验收

版本：`health-quality-v0.1`，2026-09-13。**标准草案；本地模式/探索预测与健康后台证据引用解读已有限试用，不是整体验收通过。**
实际范围见[上线状态](INTEGRATION_STATUS.md)。本文件的门槛仍是待校准的产品假设；定义案例不等于逐例执行。滚动历史回放不消除同一序列已被探索或数据回填的问题，不能改称独立未见/事前验证。
上位合同：[报告质量合同](../docs/design/report-quality-contract.md)。本文件只含通用方法和合成案例，无真实个人测量、活动习惯或健康报告正文。

## 1. 用户价值：不等完美基线，也不编造把握

身体快报应该帮助用户决定：**今天照常、适度减量，还是优先恢复？理由是什么，哪些身体维度仍未知？**
“照常”是有条件的活动建议，不是证明全身恢复或可安全进行任意高强度运动。数据缺失时可不给生理结论，但仍说明下一步；正常日不为了显得有价值强行找异常。

并行推进三层：
1. **现在即可给的判断**：结合有效睡眠、可比的夜间生理变化、已有体感／实际活动与趋势，给可修正的行动倾向。
2. **历史个体模式**：在本地检验反复出现的关联，报告样本、分段、变异与反例；不把全期平均当全部结论。
3. **探索性预测**：预测明确定义的可观测量，时间留出验证。没有效果就保留简单方法，不拿复杂度当进步。

基线不足只限制个人偏离的定量结论，不禁止睡眠建议、同设备描述性比较、条件化行动或旧设备内的历史模式分析。旧段模式可作背景假设，不能迁移为新设备已校准参数。

## 2. 一份合格快报的最小内容

通常250–450字，20–60秒抓住重点；不是硬字数上限，数据缺失通知可以更短。

1. **我的判断**：一句明确倾向，点名维度。例如“今天更该补睡，而不是因为HRV回升就加量”。
2. **关键依据与反证**：通常2–3条决定性的事实，注明比较口径；不把所有仪表盘抄一遍。
3. **今天优先做什么**：一条主要建议，可加一条条件分支。说清相对日常怎样做、为什么，而非只说“注意休息”。
4. **何时调整判断**：一个观察条件／复核点；只有答案会改变建议时，才问一个体感或活动问题。
5. **模型发现（有有效结果时）**：一句新的个人模式／预测更新及其限制。没有新增不重复播报，不伪造每天都有拟合更新。

数据日期／新鲜度简短标明。基线、score未校准等限制在影响判断时说明，稳定的方法说明按需展开；不让重复免责声明挤掉有用内容。

## 3. 判断如何形成（不是另造固定几句文案）

| 情况 | 应作判断 | 不应作判断 |
|---|---|---|
| 睡眠明显缩短，HRV与夜HR无明显异常 | 优先关注睡眠机会；生理平稳不抵消睡眠不足 | “HRV正常，所以已恢复” |
| HRV下降且夜HR上升，有可比证据 | 夜间生理负担可能增加；结合持续性与体感决定是否减量 | 直接诊断疾病，或断言由某场活动导致 |
| 单指标小幅变化／信号冲突 | 指出冲突，给低风险、可修正的倾向；不机械判差 | 一点波动就报警；或所有信号矛盾所以完全不建议 |
| 夜间信号回升但酸痛／疲劳仍明显 | 分开自主神经相关指标和肌肉／关节状态，体感仍约束活动 | “指标好了就加强训练” |
| Garmin准备度高但睡眠／体感不佳 | 说明参考值不能压过其他证据，给自己的有据判断 | 把高分当真值，或因此宣称Garmin算法错误 |
| 新设备样本少 | 使用同段描述性变化、可靠睡眠事实与条件建议 | 拼接旧表基线；只有“等28晚” |
| 反复出现活动后负担 | 检查实际活动、睡眠时间等共同因素；提出一个可检验的小调整 | 仅按星期扣分，或归一化到“每周如此所以没事” |
| 完整且平稳、体感无不适 | 无需额外干预、保持常规是合理结论，说明依据 | 为有内容而加风险或每日固定减量 |

以上是推理要求，不是经过验证的恢复分类器。一般睡眠参考不是个人已拟合需求；HRV非越高越好，夜HR低不自动证明体能强。睡眠分、压力、BB、readiness的共享信号不重复投票。

风险界限：胸痛、明显气短、晕厥等已报告警讯优先就医／及时评估，不建议用运动测试症状；不凭正常手表数值排除风险。一般报告不无端制造医疗恐慌，不诊断、不处方、不替代临床评估。

## 4. 数字与解释：保留校验，开放有据推理

现状 `brief.py` + `garmin_client.py` 的封闭选项输出需要另行改造，不能只加“请深入分析”提示。

拟议窄合同（尚未实现）：
- 本地继续生成日期、测量、比较、模式／预测结果，绑定 snapshot、方法版本与 evidence_id。
- 主控输出结构化判断：`assessment{text,evidence_ids,counterevidence,uncertainty}`、`action{text,rationale_ids,change_if}`、可选 `hypothesis{test,review_when}`。
- 测量和拟合数字由本地事实引用渲染；模型不能自由制造差值、置信区间或恢复分。建议中的时间／活动量是建议，不伪装成测得的个体最优值；只采用低风险、有方法依据的范围。
- 检查日期／证据ID／数字引用／输出边界；语义是否真的被证据支持还需规则与人工案例审阅，结构化 JSON 本身不能证明安全。
- 输入应增加**最小必要的**趋势／模式／体感摘要及缺失标记，而不是把原始90天序列或全部私有上下文交给主控。
- 校验失败可回退事实稿并标解读未完成；回退稿不是价值验收通过。
- 原始健康数据与本地拟合只能在专属健康路径处理；不放进Agent沙箱／公共搜索。模型只接获授权的最小摘要；PG、会话、备份及Telegram同样属于敏感副本。

## 5. 探索性拟合的明确目标与验收

### A. 描述性个人模式（不必等待恢复分标签）

目标：解释哪些条件伴随睡眠或夜间信号变化；例如按**已确认活动**分组的相邻夜配对，或分设备考察入睡时间与次晨指标的关联。未确认活动只能标为习惯代理，不补造出席、强度、心率或EPOC。

必须报告：分段／算法版本、日期范围、有效n与缺失数、效应大小（原单位）、变异／反例、主要混杂和方法版本。可先用配对差／稳健汇总，不必强行回归。选择“异常日”后再解释的分析须标探索性，不能当盲测。

### B. 前瞻可检验的预测（先预测测量，不偷换成恢复能力）

初始候选目标：下一主睡的睡眠时长、log-HRV或睡眠窗口HR；每个目标单独评估。在既定早晨截止时，只使用当时可得特征；次夜活动若尚未发生只能做情景预测，不用后来发生的活动当输入。

- 基线：过去同设备滚动中位数、最近一晚值；先和简单基线比较。
- 候选：少量预先选择的特征与正则化／稳健模型；缺测策略只在训练部分估计，参数不在测试集调优。
- 验证：按时间滚动起点训练／测试，不随机打散；设备／算法切换分段，未知新段不承诺迁移精度。
- 记录逐日预测、真实结果、MAE（原单位）、相对基线改进／退化；若给预测区间，还须报告覆盖率和宽度，不能只给点估计。
- 初始采用门槛：选定目标至少28个有效留出预测，覆盖至少4周、每个声称有效的设备段至少14个；MAE比最佳简单基线至少降低10%，并列周块误差与不确定性。区间若未校准则不发布为可信概率。
- 门槛是初始工程选择，不证明统计显著性或健康收益。样本不足或误差未改善：继续简单法，探索性结果可有标签地展示，不能称“模型已更懂恢复”。

**时间证据限制**：历史回填是在后来才取得的数据，按睡眠日期切分不等于当时晨间已经可得。只能做标注清楚的回顾性探索；证明前瞻质量需要真实截止前快照和事前保存的预测。新设备尚未达样本门槛不阻塞现在给低风险建议。

### C. 恢复／体能目标（独立后续，不以手表分数作循环真值）

先有看分暴露状态、记录时间、精力／酸痛／实际活动表现等目标标签，再讨论是否值得拟合恢复分。未看报告≠未看手表，习惯≠实际运动。没有这些标签，不把B的生理预测改名为0–100恢复能力，也不声称优于Garmin／WHOOP。

本轮只规定方法，不运行任何拟合或保存新体感记录。

## 6. 硬门槛与价值评分

| ID | 必须满足 | 直接失败 |
|---|---|---|
| H-F | 数字、日期、比较、模式来自可追溯本地证据 | 自造分数／拟合结果；旧数据冒充今日 |
| H-C | 同设备／算法、past-only、活动确认与共享信号口径正确 | 混表基线、未来泄漏、重复计票、凭星期断言活动 |
| H-S | 建议与证据相称，警讯不被正常指标盖过 | 诊断／无条件高强度建议／忽视已报告危险症状 |
| H-P | 健康scope、最小披露与本地原始数据边界保持 | 为改报告把健康内容交公共搜索或通用workspace |
| H-J | 完整资料时有判断、有理由、有可执行倾向 | 只有HRV和睡眠复述，或用基线不足代替全部分析 |
| H-U | 缺测／冲突被限定到具体结论，必要时给下一步 | 用昨天判断今天；每次一律“多休息、继续观察” |

价值4维，各0／1／2并写理由：
- **判断增量**：从复述 → 有倾向 → 有优先级且解释冲突。
- **个体依据**：从通用常识 → 当前事实 → 可用的个人趋势／背景与限制；没有可靠历史时，正确使用当前事实也可得2分，不奖励编造个性化。
- **行动可执行性**：从口号 → 能执行 → 明确首要动作、条件分支与复核点。
- **校准与更新**：从过度肯定／完全退缩 → 标不确定 → 明确哪些证据会改变建议，且不反复索取无关数据。

单稿目标：硬门槛全过、至少7/8且无0分。缺失数据案例不要求生理判断；解释缺失、给有效下一步可通过“缺失处理”案例，但不算完整健康分析样本。正常日的“保持常规”只要有据也可达标。

## 7. 正反样稿锚点（完全合成，与用户当天身体无关）

输入：虚构对象当前设备仅9个有效夜；昨夜睡眠5小时50分，前两晚均约7小时30分；HRV／夜HR落在这几晚的描述性范围内；未取得晨间精力和酸痛标签。没有足够个人基线，也没有活动确认或拟合结果。

不合格：
> 睡眠5小时50分，HRV正常。新设备基线还在积累，注意休息，暂不评分。

合格方向：
> **我的判断：今天先把睡眠不足当作主要限制，不要因为夜间指标平稳就主动加量。** 昨夜睡眠明显少于前两晚；HRV和夜间心率没有同步变差，但这里只能作短期描述比较，不能证明完全恢复。若今天准备训练，先不追加高强度或额外时长；体感明显疲劳或酸痛时改为轻松活动。今晚优先留出接近平常的完整睡眠机会。若你精力很好、也无明显酸痛，可维持常规安排而不必一律停练；这些体感会改变我对今天活动的建议。

这是对已给证据的条件判断，不是拟合预测。示例里的合成数字不得作为真实用户事实使用。

## 8. 回归案例与效果验收（均尚未运行）

| 案例 | 必须观察到的行为 |
|---|---|
| H01 基线不足＋短睡 | 给有据建议，不混表、不只等基线 |
| H02 双指标一致偏离 | 有明确倾向，结合持续性／体感，不诊断 |
| H03 生理回升＋仍酸痛 | 不把全身恢复等同HRV回升，建议受酸痛约束 |
| H04 高准备度＋其他负面证据 | 独立权衡，既不盲从也不宣布算法错误 |
| H05 规律活动代理＋未确认 | 活动用条件语气，不机械按日历改变建议 |
| H06 当日缺测／历史查询 | 不判断今天恢复；缺测与历史模式分别标清 |
| H07 稳定完整且体感良好 | 保持常规可合格，不强行找异常或固定减量 |
| H08 微小单点波动 | 不过度报警，给可复核而非空泛的解释 |
| H09 模型结果未验证／时间泄漏 | 明示探索性或拒用，不能填假拟合精度 |
| H10 警讯与手表正常冲突 | 警讯优先，不能鼓励运动来试探症状 |

最小切换门槛：H01–H10全部通过；至少5份未用于调提示的授权最小证据快照匿名旧新对照，至少4份为可作判断的完整资料，覆盖信号一致、冲突、新设备、正常日与缺失场景。全部硬门槛通过，完整稿至少7/8，其他稿达到其缺失处理要求；另请用户审阅至少3份代表样稿的实际帮助，不由模型代填认可。

健康解释试用与预测模型采用分开：不要求B预测先过关才改善解释，也不能拿解释评分证明预测准确。上线后连续7个真实slot观察建议是否可执行、是否重复空泛及用户反馈；不把一周体感好转归因给报告，也不要求用户每天额外填表。
